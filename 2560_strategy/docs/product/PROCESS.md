# 研发过程管理文档

## 1. 管理目标

后续开发需要把“想做什么、为什么做、做到什么程度、怎么验收、如何上线”固定下来。所有需求必须能追溯到 PRD、路线图、任务、代码变更、测试结果和上线记录。

## 2. 工作流

```text
需求提出
  -> PRD/需求卡确认
  -> 技术方案
  -> 任务拆分
  -> 开发实现
  -> 自测和自动化测试
  -> 代码评审
  -> 验收
  -> 发布
  -> 复盘
```

## 3. 角色职责

### 产品负责人

- 维护 PRD、路线图和优先级。
- 定义用户价值、验收标准和非目标。
- 每个阶段结束后确认是否进入下一阶段。

### 技术负责人

- 拆解技术方案。
- 控制架构边界：新功能进入 React + `/api/v1`。
- 管理 legacy 下线计划。
- 决定测试覆盖范围。

### 开发者

- 按任务卡实现。
- 保持改动范围清晰。
- 补充必要测试。
- 更新对应文档。

### 测试/验收负责人

- 维护验收用例。
- 执行回归。
- 记录缺陷和阻塞。

## 6. 任务拆分规则

任务粒度建议控制在 0.5-2 天内完成。一个任务应尽量只有一个明确产物。

拆分维度：

- 后端 API。
- 数据模型或迁移。
- 前端页面。
- 组件和交互。
- 测试。
- 文档。
- 运维和发布。

任务状态：

- Todo：未开始。
- In Progress：开发中。
- Review：待评审。
- QA：待验收。
- Done：已完成并验证。
- Blocked：被依赖或环境阻塞。

## 7. 分支和提交规范

分支命名：

```text
codex/<topic>
feature/<topic>
fix/<topic>
docs/<topic>
```

提交信息建议：

```text
feat: add scan result polling
fix: prevent mock data from silent usage
docs: add product roadmap
test: cover pick status transitions
```

提交前必须确认：

- 没有混入 `node_modules`、`venv`、`__pycache__`、`.pyc`、日志、缓存和本地数据库。
- 文档和代码变更属于同一需求。
- 验证命令已执行并记录。

## 8. 质量门禁

### 每次代码变更至少执行

```powershell
npm test
npm run build
docker compose config --quiet
```

### 涉及后端必须执行

```powershell
python -m pytest
```

### 涉及权限、安全、租户必须覆盖

- 未登录访问。
- viewer 只读。
- editor 写业务但不能管理用户。
- admin 管理权限。
- 非绑定租户拒绝访问。
- CSRF 缺失拒绝写操作。

### 涉及任务队列必须覆盖

- pending。
- running。
- completed。
- failed。
- cancelled。
- retrying。
- stale。

### 涉及行情源必须覆盖

- primary provider 可用。
- fallback provider 生效。
- mock 数据警示。
- provider chain 和错误原因展示。

## 9. 验收规范

验收分四层：

### 产品验收

- 用户主流程是否走通。
- 页面文案是否准确。
- 数据质量和风险是否可见。
- 无权限和空状态是否清晰。

### 技术验收

- API 响应结构稳定。
- 分页、过滤、排序符合约定。
- 错误信息明确。
- 无明显重复逻辑和跨层调用。

### 安全验收

- 写操作有 CSRF。
- 租户隔离正确。
- 审计记录完整。
- 敏感字段脱敏。

### 运维验收

- 日志可定位。
- 任务失败可解释。
- 配置项有默认和示例。
- 容器构建可复现。

## 10. 发布流程

### 发布前

1. 确认需求卡全部 Done。
2. 确认测试通过。
3. 确认数据库迁移脚本。
4. 确认回滚方式。
5. 更新变更记录。

### 发布中

1. 备份数据库和关键数据目录。
2. 部署后端。
3. 部署前端。
4. 执行健康检查。
5. 执行关键业务冒烟：登录、扫描、入池、回测、任务列表。

### 发布后

1. 观察日志和任务失败率。
2. 检查用户反馈。
3. 记录遗留问题。
4. 更新 roadmap 状态。

## 11. 缺陷管理

缺陷优先级：

- P0：系统不可用、数据损坏、权限越权、生产安全风险。
- P1：主流程阻塞，例如无法扫描、无法入池、无法复盘。
- P2：重要功能异常但有绕行方式。
- P3：文案、样式、非关键体验问题。

缺陷必须记录：

- 复现步骤。
- 实际结果。
- 预期结果。
- 影响范围。
- 日志或截图。
- 修复版本。

## 12. 文档维护规则

- PRD 变更必须同步 ROADMAP。
- 功能上线必须更新验收状态。
- API 行为变化必须更新 API 文档或测试。
- 运维行为变化必须更新 runbook。
- legacy 下线必须更新下线计划。
